# 说明与限制

## 版本与平台

- 在 DSH `0.2.2-rc.1` 桌面版上测试（构建使用公开的 `@deepseek-ai/dsh-client-ui-*` `0.1.6-alpha.2` 契约包）；DSH 更新可能改动界面扩展点与会话存储格式，需要跟随适配。
- macOS 与 Linux 是已测试目标；Windows 未测试（开发测试套件依赖 POSIX 的 `chmod` 与符号链接）。
- `npm run smoke` 需要已登录的外部 CLI，`npm run sim` 是 stub 环境模拟——两者都只用于本地手动验证，不能替代 CI 里的 `npm test`。
- 可选集成（GitLab / GitHub、阿里云 DMS / SLS、PingCode、skills.sh）需要先安装并登录对应 CLI；缺失时只影响对应页面，不影响工作台其余部分。

## 平台与 CLI

- 平台识别完全自动：GitLab 自建实例若不在 `glab auth status` 列表、host 也不是已知域名，就无法识别，该实例的仓库不可用。
- 依赖本机对应 CLI 已登录；未登录时面板给出明确提示。个别 CLI 实验性子命令在部分版本有 bug，插件不使用它们。
- 两端语义差异（GitLab 的 reviewer 不会自动移除、GitHub 无服务端分页等）及其处理方式见 [conventions](conventions.md)。

## 列表与分页

- 列表与徽标受一次 CLI 拉取上限约束：数据不足上限时总数精确，打满上限时只显示前若干条；「全部」页签不保证完整。
- DMS 工单列表（待审批 / 全部 / 我的）都只拉第一页，超出时提示「共 N 条，当前显示前 50 条」；翻页尚未实现。
- 工单内容详情按类型覆盖：结构同步（语句超过页数上限会截断并提示）、数据变更同族 `DC_*`（以附件提交时 API 不返回正文，需到 DMS 控制台下载）、SQL 结果集导出、数据库导出、数据追踪、数据归档、权限与 Owner 申请、结构设计 `NDDL`（正文取自发布记录 `ListDDLPublishRecords`，按发布任务翻出各表脚本）。无 SQL 的类型只展示 API 返回的配置项（数据库导出的下载地址是带签名的临时链接，可能过期）。数据生成等其余类型仍提示暂不支持；数据库导出 / 数据追踪 / 数据归档三条路径按官方响应结构实现，未在真实工单上验证过。

## 评审

- 「评审」只在能解析出对应工作区时出现：面板选中的工作区，或某个已注册工作区的 git remote 与 MR/PR 仓库一致（且该实例已授权）。
- 自动评审依赖 DSH host 会话服务与本机已登录的 CLI；DSH 进程停止期间不会执行。旧 DSH 仅支持客户端手动评审。
- 历史索引受保留策略限制，但精确去重标记仍随已评提交增长；清理工作台记录不会删除 DSH 会话日志。
- 任务记录由单个 host 进程持有；多个 DSH 部署应配置各自的记录文件，不支持共享文件的并发调度。
- 自动评审范围默认只评「指派给我为 reviewer」的非草稿项，可逐仓库扩为含我提交的或全部。列表达到部署上限时停止扫描并报错，避免误把截断结果当成完整基线。
- 等待用户处理或无法核实的运行任务会暂停后续启动，需要打开原会话处理。自动评审默认由会话代理直接发布评论（可关闭发布，关闭时只在会话内出报告）；版本或已有评论无法核实时停止发布。评论标记去重依赖代理执行，平台不提供原子去重保证。
- 只读评审依靠指令与 DSH 原有工具权限策略，插件没有新增强制只读沙箱。评审不切换主工作区分支、不修改工作区；需要运行测试或复现时，允许用 `git worktree` 在临时目录检出评审版本，结束后删除。

## Issue 处理

- 「处理」同样只在能解析出对应工作区时出现，且只给**开启中**的 Issue（关闭的要先重新打开）。
- 与「评审」共用同一条会话桥：复用空白会话或新建，每次点击一个独立会话，不影响当前会话。
- 默认提示词把本轮限定为「仅分析、确认问题」——不改代码、不提交、不关单、不发表评论；要落地修复需在该会话里继续下指令，或先定制「Issue 处理提示词」。
- 处理**不新增 host 路由**：提示词只用客户端已有的 Issue 数据渲染，CLI 命令由 Agent 在工作区里执行——因此**依赖该工作区就是该 Issue 的仓库**。

## SLS 日志

- 依赖 `aliyun` 已登录，且目标 Project / Logstore 已开通并配置索引；没有默认 Project，环境列表来自插件行配置 `slsEnvironments`（JSON 非法按空列表处理，单条不合法会被忽略），新增环境只需改配置、无需改代码。未配置时页面回落为手填 Project / Logstore；未配置索引时显示服务端返回的错误原文。
- 每次查询实时执行、不缓存；单次返回条数与累计翻页都有上限，整批返回时可用「加载更多」按 offset 追加。
- 时间范围左闭右开，起止相同会被拒绝。
- SQL 分析模式（查询语句含 `|`）下 offset 翻页无效，需用 `LIMIT`。
- duration 按 OTEL span 惯例以**微秒**解释；查非 trace 类 Logstore 且该字段另有单位时，换算出的时长会失真（原始值仍在 JSON 页签）。
- 详情 / SQL / JSON 是启发式映射：非 DB 日志可能没有 SQL 页签；JSON 嵌套解析有层数与行数上限，超大字段可能被截断（「复制 JSON」仍是原始全文）。
- 相对快捷区间每次查询按「现在」重算；手动改过起止后 chip 不再命中，以输入框为准。
- 瀑布视图只对带 `start` / `end` 的条目生效；父子层级按当前结果集推算，父 span 不在结果内时该 span 顶格显示；固定时间窗内新写入的日志可能造成相邻页少量重复。

## PingCode 研发管理

- 依赖本机 `python3` 与 pingcode 技能目录（`scripts/api_call.py` + `.env`）；技能目录默认探测 `~/.agents/skills/pingcode` / `~/.workbuddy/skills/pingcode`，也可用插件行配置的 `pingcodeSkillDir` 显式指定。
- 令牌两种模式：企业令牌无人值守；用户令牌有效期 30 天，过期后需重新运行技能 `auth_user.py`（浏览器授权），面板内无法完成续期。
- 「我创建的」依赖用户令牌（`/v1/myself` 仅用户令牌可读）；企业令牌模式下该筛选会报无权限。
- 接口限流每分钟 200 次：宿主分级缓存压频，狂点刷新仍可能触发限流。
- 状态分类（待处理 / 挂起 / 进行中 / 已完成 / 已关闭）是**服务端过滤**；「挂起」没有独立的 `state.type`，按系统态名（挂起 / Suspended）识别——组织若把挂起态改成其他名字，该桶识别不到，自定义态也被 search 拒绝（100044）。
- 只读（阶段一）：创建 / 更新工作项、评论、工时等写操作尚未接入。

## 技能管理（skills.sh / `npx skills`）

- 安装 / 卸载 / 更新走本机 `npx skills` CLI：需要 node + npx，首次运行会**联网拉取 skills 包**（默认 `skills@latest`，可用 `skillsCliSpec` 钉版本或指向本机已装的可执行文件）；CLI 不可用时页面只读。
- 技能目录搜索走 skills.sh 的**公开** `/api/search` 端点；文档里的 `/api/v1/*`（排行 / 趋势 / 详情 / 审计）需要 Vercel OIDC 令牌，插件拿不到，故没有排行 / 趋势 / 安全审计视图——`/api/search` 是 CLI 的 `find` 同源接口，无需任何令牌。
- `skills update` 无 JSON 输出，按文本报告判定「已是最新 / 更新了哪些」；只识别明确的「up to date / No … skills to update」措辞与 `Updated <name>` 行，**无法识别的措辞既不谎报「已是最新」，也不列更新项**——界面按「更新完成」处理。
- 列表 / 详情直接读 DSH 技能发现根，**不经过 CLI**：只出现在 `.dsh/skills`（DSH 专有根）的技能标「非 CLI 管理」，卸载对它禁用（CLI 不认识该根，`npx skills remove` 会拒绝）；作用域级「检查更新」只会处理 CLI 认识的技能。
- 作用域与落点：global 默认 `~/.agents/skills`（所有 DSH 工作区可用），project 为当前工作区 `.agents/skills`；`--copy` 默认开启（文件真落到目标根）。装了 **universal / zed 之外** agent 的全局技能（`~/.claude/skills` 等）DSH **读不到**，界面只在选择其它 agent 时提示，不拦截。
- 停用 / 启用是**纯文件改动**（编辑 SKILL.md frontmatter 的 `disable-model-invocation` 标记），不需要 skills CLI；但会改变本地 SKILL.md，与来源指纹不同——**停用中的技能不参与「检查更新」**（单独标「已停用」），且**「更新全部」会把该标记覆盖回来源版本（技能被重新启用）**。需要用户先启用再更新。
- 依赖网络：`npx skills` 首次引导与搜索都要访问外网；内网 / 离线环境只有「已装列表 + 本地详情浏览」可用。
- 详情页的文件树只列技能目录内的前 50 个文件（跳过 `node_modules` / `.git`）。支持文件按类型只读渲染：Markdown 排版、代码 / 配置（含 JSON）语法高亮、CSV/TSV 表格、`.env` 键值表、图片内联预览，其余按纯文本。上限：图片 2MB 以内才内联预览，超过 200KB 的源码不交给高亮器（大文件分词会卡面板），表格与键值表只预览前 200 行，正文超过 256KB 截断显示。
- 安装 / 卸载是真实写操作：会改动 `~/.agents/skills` 等本机目录；DSH 的 skill-filesystem provider 监听这些根，新技能通常会在新会话里生效。

## 首页（需要我关注的汇总）

- 会话区直接读 **DSH 自身的会话存储**（`$DSH_HOME/sessions` 下的 `session.v{N}.jsonl(.zstd)` 与 `storages/session_projcache.json`），**不是官方契约**——DSH 升级若改动存储格式，需要随版本跟进解析；解析失败会降级（该会话少些字段或直接剔除），不会让首页报错。
- 「进行中」优先取宿主会话列表的运行状态（与侧边栏状态点同源）；仅当宿主列表未覆盖该会话时才退回 `session.lock` 的 flock 探测——flock 是写柄租约，会话在 GUI 里开着即被持有、与是否正在产出无关，兜底值可能把"开着但已结束"的会话误报为进行中。flock 探测依赖本机 `python3`（与 PingCode 同款软依赖），缺失时全部按「非进行中」处理，最近活跃仍正常。
- 「待处理」依赖 projcache 里的统计（开放步骤 / 挂起工具调用），只覆盖近期有投影的会话；老会话缺该数据时按普通最近活跃展示。
- 「待交互」（审批 / 计划待审 / 待回答）不依赖上述本地存储，取客户端 `uiSession.sessionStatus.pendingInteraction`（侧边栏状态点同源），因此老会话也能识别、且优先于「进行中」——宿主在等待审批时仍报运行中，只看运行会把「在等你」画成进行中；其它域自带的 pending 请求（如插件审批）侧边栏不展示，首页同样忽略。
- 过滤窗口固定：进行中 / 待处理 / 待交互无条件保留，最近活跃只留近 24h、上限 10 条；超过 48h 无活动且非进行中的会话不会出现在首页（仍可去对应工作区的会话列表查看）。

## 安全与依赖

- 客户端代码按「随包分发的受信静态代码」运行，**无人工审批**——请只安装你信任的包。
- 路由仅同源页面可读；插件**不保存任何凭据**，每次通过你本机的 CLI 读取你自己账号的数据。
- DMS 审批的对象是**审批流实例**，不是工单号本身；解析不出时给出明确错误。
- 依赖 DSH 的界面扩展点（侧边栏与主面板槽位）；DSH 大幅改版后可能需要适配。
- 不要把 DSH Web 暴露给不可信网络：能打开页面的人即可用你已登录的凭据驱动本机 CLI。

## 功能开关

- 开关是**按人、按浏览器**的界面与请求裁剪（localStorage）：只影响本机当前使用者，host 路由仍然注册，别的浏览器 / 别的使用者不受影响。这不是权限边界，也没有部署级（整机 / 全组）开关——要按部署整体关掉某个域，目前只能自行裁剪客户端代码。
- 关闭某个域会丢掉该页的列表状态（重新开启后从干净状态进入）；关闭期间也不缓存该域数据，重新开启后的首屏需要现拉一次。
