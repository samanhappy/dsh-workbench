# 代码约定

这里只写**必须守住、且从代码里不容易看出来**的约定。实现细节以源码与测试为准。

## 安全边界

- **白名单式 CLI argv**：所有路由只构造固定的 argv，绝不把用户输入拼进 shell；每个外部参数都要有取值校验与上限收敛。
- **凭据不落地**：插件不保存任何 AccessKey / token，每次通过本机已登录的 CLI 读取数据。
- **同源信任围栏**：路由沿用 DSH 的连接信任围栏，仅同源页面可读。
- **远端富文本先清洗再渲染**：PingCode 描述/评论等远端 HTML 必须经 host 的白名单重序列化（`sanitizeRichText`：标签/属性白名单、URL scheme 白名单、正文转义、结构补闭合）才允许进客户端 `dangerouslySetInnerHTML`；接入新的远端富文本来源时必须复用这条链路。
- 客户端代码按「随包分发的受信静态代码」运行（无人工审批）——安装即信任。

## 本地 Git

Git 操作限于 DSH 工作区，危险操作需页面内确认；推送不允许 force。
所有远端推送入口点击即执行，目标为仓库已配置的全部 remote。
指定远端推送使用当前分支的同名目标，不改变 upstream；多远端分别执行，部分失败不回滚已成功的推送。
拉取仅允许快进更新，分支分叉时交由用户在终端处理，不自动合并或 rebase。
合并冲突保留在工作区供人工处理，提交后推送失败不回滚提交。
AI 与提交共享范围：有暂存内容时仅处理暂存内容，否则处理全部待提交变更；仅提交操作会自动暂存，AI 生成不修改暂存区。
AI 提交信息会将选定改动发送给所选 DSH 模型，功能开关不构成权限边界。
工作台代表操作者执行 Git：宿主进程的 `GIT_CONFIG_GLOBAL` 指向 DSH 目录时（同进程插件为自身子进程注入的隔离配置），改用操作者 home 下的全局配置；其余取值视为操作者本意，不覆盖。这套隔离同时关闭机器级 git 配置（`GIT_CONFIG_NOSYSTEM`），而 macOS 的 `osxkeychain` 凭据助手配置在那里——恢复操作者配置时必须一并恢复，否则推送无法认证。
提交失败必须同时出现在提交卡片与 toast 里（卡片可能是折叠态）；仓库没有 git 身份时禁用提交并说明，避免先暂存再被 `git commit` 拒绝。

## 缓存与失效

- 分级缓存（列表 / 状态 / CLI 登录探测）＋ 写操作即时失效；日志查询等时效敏感能力不缓存。
- 缓存 TTL 与上限是**部署可调参数**，定义在 `src/host/config.ts`；不要在文档或业务代码里散落硬编码数值。
- 客户端不做长缓存：共享 store 只负责把同一时间窗内多个消费者的请求合并成一次。

## 配置注册表（用户可定制文本与功能开关）

一套「注册表 + 存取层 + 设置面板」三元组，新增配置**只需往注册表加一项**：

- 每项声明 `key` / `label` / `kind` / `scope` / `default`，可选 `placeholders` 与 `help`。
- `scope` 是注册表分域标记（`'forge'` = 仓库页提示词与评审设置，`'home'` = 首页显示选项，`'global'`（缺省）= 全局功能与开关）；配置页以 `'all'` 渲染全部项并按 scope 与 key 分组，将来按入口拆分面板时按 scope 过滤。
- `kind` 决定面板控件：`'prompt'` = 文本类，业务代码经 `resolveConfigText(key, vars)` 取生效值；`'toggle'` = 开关类，经 `resolveConfigToggle(key)` 取生效值、`setConfigToggle` 写入（开启等于注册表默认时清除覆盖）。
- 覆盖值存本机 localStorage（按人隔离），留空即回退默认；任何写入都会推进配置 revision 并广播（`subscribeConfig`），功能开关相关 UI 与外壳轮询据此即时重渲染——新增写入路径必须走 save/reset。
- 「全部恢复默认」按 scope 只清本面板的 key，不得波及其他域。
- 部署级参数（如 `slsEnvironments`）**不在**这个按人注册表里，见下一节。

## 部署可调参数（插件行 config）

与上面的按人配置注册表不同，`src/host/config.ts` 是**部署级**参数：写在 DSH profile 的插件行 `config` 里，所有连接该 DSH 的使用者共享。新增参数只在 schema 加字段，文档不复述默认值。

- `slsEnvironments`：SLS 环境列表，JSON 字符串数组，元素 `{ key, label, project, logstore, logs? }`。**没有默认 Project**：未配置时页面回落为手填 Project / Logstore；JSON 非法 / 非数组按空列表降级，单条不合法只忽略该条，不能因此让插件启动失败。
- 部署参数不是权限边界：host 路由始终注册，参数只影响数据来源与频率。

## 功能开关（功能域裁剪）

- 七个功能域（`feature.forge` / `feature.git` / `feature.dms` / `feature.sls` / `feature.pingcode` / `feature.skills` / `feature.notifications`）默认开启；关闭 = 隐藏页签与侧边栏常显快捷入口 + 不挂载该功能页 + 不再请求该域路由（外壳轮询同样跳过）。「配置」页不受开关约束，否则全部关闭后无法恢复。
- 侧边栏常显快捷入口另有逐项开关（`shortcut.*`），只影响侧栏显示，仍受功能总开关约束；Git 没有独立快捷入口，随仓库页入口出现。
- 通知是唯一的例外形态：列表页**从不**设页签与侧栏常显入口（入口收敛到首页），开关只裁剪首页通知区 / 统计卡与列表页挂载。
- 开关值按人存在本机浏览器，业务侧只经 `features.ts` 读取，不直接拼 key。
- **这不是权限边界**：host 路由仍然注册（同源围栏不变），关闭只是使用者自己的界面与请求裁剪。
- 技能开关只关界面与页面触发的 CLI 调用：**已装技能由 DSH 的 skill-filesystem 直接加载**，与这个开关无关（关掉不会让技能失效）。

## 技能管理外部契约

写错会出问题、且从代码里不容易看全的部分：

- **两条数据链路，别混用**：
  - 安装 / 卸载 / 更新只走 `npx skills` CLI——来源解析、GitHub 认证、多 agent 分发都封装在 CLI 里，插件不自己下载仓库。
  - 列表 / 详情**直接读 DSH 技能发现根**（`~/.agents/skills`、`<工作区>/.agents/skills`，及 `.dsh/skills` 备用根），不走 CLI 的 `ls`（CLI 会扫描所有 agent 目录并把「DSH 读不到」的技能混进来）。因此「CLI 不可用」时列表 / 预览仍可用，只有写操作会失败。
  - 目录搜索走 skills.sh **公开** `/api/search`（CLI 的 `find` 同源、无需令牌）；`/api/v1/*` 需要 Vercel OIDC 令牌，**不接入**。
- **作用域与落点**：scope 白名单 `global`（默认，`~/.agents/skills`）/ `project`（`<工作区>/.agents/skills`）；真正的落点路径由 CLI 决定并回传，插件不复刻 agent × 路径表。目标 agent id 白名单见 host `SKILL_AGENTS`；`universal` 的 global 落点就是 DSH 的 `~/.agents/skills`，其它 agent 的 global 目标 DSH 读不到（界面提示、不拦截）。
- **argv 构造**：所有 `buildSkills*Argv` 只返回**子命令参数**（`['add' …]` 等），`npx --yes <spec>` 前缀由执行层统一加（`withSkillsCliPrefix`）——两个 `buildSkills*Argv` 不能互相嵌套，否则产生双重前缀。
- **copy 默认开启**（`--copy`）：CLI 对部分 agent 默认建符号链接指向自己的 canonical 目录；copy 让文件真落到目标根。显式 `copy:false` 才关。
- **安装前枚举**使用 CLI 的只读 list 模式，它不能与 JSON 模式组合；枚举失败或输出无法识别必须报错，不能当作空来源。
- **CLI JSON 契约**：`add --json` / `ls --json` 输出里混有横幅 / 安全审计框 / ANSI 色，解析前必须剥 ANSI 并截取第一个 JSON 数组（`parseSkillsJsonArray`）；`remove --json` 成功时**不产出 JSON**，以退出码 + 目录是否还在为准；`update` **无 JSON**，按文本报告判定「已是最新 / 更新了哪些」。
- **只读更新检测**比较 CLI 安装记录与 GitHub 来源指纹，不调用 CLI 的 `check`
  （部分版本将它视作更新别名）。缺少记录、不支持的来源或检测失败都属于「无法检测」，
  不能视作「已是最新」；目前支持 GitHub 来源，安装候选只过滤同来源已确认最新的技能。
- **停用 / 启用是第三条数据链路，只走本地文件，不碰 CLI**：读写 SKILL.md frontmatter 的
  `disable-model-invocation` 标记（DSH 原生字段：`true` = 模型不再自动触发、文件保留）。
  前端 frontmatter 的解析必须与 DSH 的 `frontmatterBoolean` 语义一致（true/1/yes/on），
  改写用行级编辑（`editSkillInvocationFlag`：只增删这一个顶层键，正文与其余字段、CRLF
  行尾原样保留，无有效 frontmatter 报错不写）；写盘先写临时文件再 rename（原子）。因
  为改动会改变技能指纹，**停用中的技能在更新检测里直接标 `disabled`、跳过来源比较**
  （更新会把标记覆盖回来源版本），安装候选同样把它视为「已装」而非可更新项。
- **自动更新**由 host 生命周期驱动，不依赖页面打开或浏览器功能开关；覆盖全局和 host 当前工作区，使用 CLI 锁文件记录的来源。部署可关闭自动更新；未被 CLI 跟踪的手写技能不受管理。失败不阻断工作台，下一轮重试；卸载插件停止后续调度。
- **npm 缓存**：`npx` 默认写 `~/.npm`；沙箱 / 无写权限环境用配置 `skillsNpmCacheDir` 把 `npm_config_cache` 指到可写目录（作为 spawn env 传入，不是 argv）。
- **类名作用域**：技能页的表单栅格用 `wb-sk-*` 前缀，**不得复用 `wb-sls-*`**——`wb-sls-form` 是 SLS 页「是否挂载」的判定锚点（sim-panel 与测试都靠它）。
- **SKILL.md 与支持文件都是外部内容**：只做只读渲染，客户端 Markdown 渲染生成 React 元素（无 innerHTML），链接只放行 http/https/mailto/相对路径；指向技能内文件的相对链接改由详情页页内打开，不外跳。
- **非 Markdown 支持文件按类型换渲染器**，但仍是只读：代码 / 配置（含 JSON）交给宿主的 `CodeBlock`（shiki，语法名由扩展名映射）、CSV/TSV 与 `.env` 渲染成表格（客户端纯函数解析）、图片只呈现 host 内联的 `data:image/*;base64,`。宿主缺这些 primitive 时降级为纯文本——老 profile 不会白屏。**不得**自己拼 HTML 或 `<img src>` 直连任意字符串。
- **详情页按需读取技能内单个支持文件**：只接受技能目录内的相对路径，绝对路径、`..` 段与指向目录外的符号链接一律拒绝（realpath 二次校验）；图片按上限内联成 data URL，其余二进制只回报体积不回正文，超长正文截断。

## 流程契约

- **评审**不改码、不切换主工作区分支、不修改工作区、不批准、不合并（需要跑测试/复现时用 `git worktree` 临时检出，结束后删除）；手动与自动评审共用同一份提示词。手动评审直接发表平台评论（评论语言跟随 MR/PR）；自动评审是否发表评论按默认与逐仓库设置（`defaults.publish` / 仓库 `publish`，缺省与 `'inherit'` 都跟随默认，默认未设时发表），发表前核实源提交并检查评论标记，不发表时只在会话内出报告、同样核实源提交。
- 手动与自动评审共享 host 任务记录。同一仓库与源提交复用任务，基准提交变化只使报告过期；重新执行必须显式选择，失败不自动重试。
- 自动评审需要逐仓库开启；开启时现有待评审项只记为基线。评审范围（指派给我为 reviewer / 加我提交的 / 全部）与「是否自动发表评论」逐仓库可配、未显式配置时跟随默认；「指派给我」口径始终剔除我已批准的 MR。后台配置属于本机 host，所有连接的浏览器共享，不受浏览器功能开关控制。
- 推送触发的自动评审可配置冷却窗口（部署默认 5 分钟，`defaults.cooldownMs` 覆盖，0 关闭）：窗口内同一 MR/PR 的多次推送合并为一次评审，只评窗口结束后的最新提交；手动评审不受冷却限制。
- 已结束任务只保留有限历史索引；完整报告归 DSH 会话管理。清理索引仍保留提交版本的去重标记，不能因历史清理再次自动消费；运行或状态不确定的任务保留恢复数据。
- 指令接收不等于评审完成；以 DSH 会话事件核实结果，状态不确定时保留原会话，避免再次消费。
- 指定评审模型会同时更新 DSH 全局默认模型。host 任务选择失败即报错，不静默降级；旧 DSH 的客户端手动回退保留原有降级行为。
- **处理**：同一套会话桥，命名「处理 #编号 标题」，提交 `prompt.issue`；本轮只做分析与确认——不改代码、不提交、不关单、不评论。入口只在 Issue 开启中、且能解析出对应工作区时出现。
- 客户端会话类操作复用 `src/client/session.ts`，后台评审复用官方 host 会话服务；不另建执行器。
- 会话类能力的失败要**结构化返回**（区分「服务不可用 / 会话无法发送 / 发送失败」），由各调用点决定文案。

## 平台语义差异

代码里看不出来、但必须知道「为什么两端不一样」的部分：

- **批准 / 待评审**：GitHub 提交 review 后会自动撤掉 review request；GitLab 不会，所以「待评审」要在 `--reviewer @me` 之上补一次 GraphQL approvedBy 覆盖层剔除我已批准的 MR（老版 REST 无对应参数），覆盖层失败时回退未过滤列表。
- **分页**：GitLab 列表可服务端分页并给出精确总数；GitHub 只能取回后本地切片，总数未知。
- **搜索**：GitLab 的全文检索对 CJK / 编号不可靠，所以纯数字搜索词按编号直查；GitHub 的排序没有独立旗标，用搜索限定符表达。
- **关联关系**：GitLab 有专门的关联 MR 接口；GitHub 只有「由 PR 关闭」这一种关系，缺失属正常。
- **平台归属**：仓库 host 归哪个平台由 `glab auth status --all` / `gh auth status` 判定。这两个命令会顺带探测各实例的 API：断网或实例不可达时它们仍打印「x <host>: API call failed」+「✓ Token found」（glab）或「Failed to log in to <host> account」（gh）。这类输出必须仍算「已登录」，否则一次网络抖动就会把关联正常的仓库读成「未在登录列表」，所有请求变成误导性的平台错误；只有 401（token 真的不可用）不算。
- **归一化**：两端数据必须先折成同一套视图字段，UI 才渲染——新增平台字段时先补归一化，不要在组件里分支平台。

## Issues 口径

列表固定全仓库数据、默认只看未关闭；更新走**增量字段**（标签 / 负责人的增删），不做整表覆盖。

## UI 状态规则

- 页面与二级导航的组件**常挂载**（display 切换），列表状态跨页签保留；未激活的半区不发任何请求。配置页例外：纯客户端无列表状态，按需挂载（离开即卸载，展开态不保留）。被功能开关关掉的功能页**不挂载**（关闭期间不保留其列表状态）。首页例外：聚合页无功能开关，恒挂载，但各区块内容受对应开关约束。
- 当前页被开关关掉时立即落到仍开启的第一个功能页（全关则配置页）并持久化，不留「页签都不存在却仍显示某页」的中间态。
- 刷新由外壳轮询 + 心跳驱动，面板不各自起定时器；轮询只预热已开启的功能域。**唯一例外**：首页打开时有一个 60s 轻轮询只刷 `/home/sessions`（进行中状态时效敏感，历史首次扫描需解析候选日志，后续复用未变更日志的解析缓存；外壳轮询照常预热其它域）。
- 首页「最近完成」只放已读完成的归档（查看后仍保留，历史可继续向下加载，不受近期活动窗口限制），按最后活动时间倒序、行尾也显示最后活动；未读完成在「活跃会话」里提醒，打开会话即归入右栏。后台常驻会话（按会话的 agent preset 判定，见 `HOME_BACKGROUND_PRESETS`）行上标「后台」并以虚线描边，两栏各自可在「全部 / 剔除后台」间过滤；这是视图过滤，不改变 host 的保留口径。
- 用户可见偏好（上次所在页、二级导航、DMS Region/Tid、SLS 环境与数据类型）持久化在本机 localStorage。

- SLS 支持普通日志、Trace 和同时查询；同时查询共用时间范围和查询语句，SQL 分别执行，结果、错误与分页各自独立。两者独立保留查询语句，日志中的 traceID 关联到同环境、同时间范围的 Trace。

## DMS 工单范围

“待审批”是当前账号作为处理人（`AS_HANDLER`）的工单，按配置的提交人姓名精确匹配；
“全部”在同一处理人范围内不再按提交人过滤。“我的”切换为提交人视角（`AS_COMMITTER`），
列出当前账号提交的工单，只读展示、不提供审批动作——审批仍从处理人视角进行。
提交人配置只影响前两个视图，不改变 DMS 本身的审批权限。
