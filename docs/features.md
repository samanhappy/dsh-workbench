# 功能说明

工作台打开时的默认落地页是**首页**（需要我关注的汇总），其余功能页 + 一个配置页在同一面板里（顶部页签切换，「主页」占第一个页签，点页签栏空白处或侧边栏「工作台」行（行内常显快捷入口外）同样回首页；功能页组件常挂载、状态跨页签保留）：**仓库页**内是 `Git | MR / PR | Issues | 自动评审` 二级导航，MR/PR、Issues 与自动评审基于本机 `glab` / `gh`，Git 子页不需要远程 CLI；**DMS页**与 **SLS页**基于本机 `aliyun`，**PingCode 页**基于本机 `python3` 驱动的 pingcode 技能脚本（`api_call.py`），**技能管理页**基于 skills.sh 的 `npx skills` CLI 与本机技能目录，**配置页**承载按人定制的配置项（按需挂载）。

GitLab/GitHub、阿里云、PingCode 与 skills.sh 都是**可选集成**：不安装 / 未登录对应 CLI 时，只影响相关页面与动作，首页会话区、本地 Git、配置与技能只读浏览不受影响。这里只列能力；参数、命令与交互细节以源码为准。

## 首页（需要我关注的汇总）

打开工作台默认落在首页。三块内容：

| 能力 | 说明 |
| --- | --- |
| 关注点统计卡 | 进行中会话（跨工作区）/ 待评审 MR（当前工作区）/ 待审批 DMS / GitHub 未读，可点击直达对应页；各卡受对应功能开关约束（关掉即隐藏） |
| 活跃会话（左栏） | **跨工作区**聚合（host 读 `$DSH_HOME/sessions` + projcache），剔除空白会话与子会话；收进行中 / 待处理 / 待交互（等你审批 / 回答，恒保留）/ 未读完成（绿点 + 加粗，表示「结果还没看过」）的会话，**需要你动手的置顶**，其后是进行中，最后是未读完成；有待交互时行尾换成状态胶囊（待审批 / 计划待审 / 待回答，与侧边栏 `trailingLabel` 同值） |
| 最近完成（右栏） | 已读完成的归档：行首不占状态槽位、不画状态点，查看后仍保留；历史可向下滚动加载。未读完成打开后即归入本栏——未读只能通过打开会话消除（宿主没有「标为已读」接口） |
| 会话行（两栏共用） | 状态点只在左栏（右栏是纯归档，行首不留空槽位）；时间、工作区名都与侧边栏同源：状态取 `uiSession.sessionStatus`（待交互 > 进行中 > 待处理 > 未读完成），时间是最后一条用户消息（助手活动不推进），工作区名取宿主注册表、未注册回退 cwd 末段；点击行在主视图打开该会话；列表随内容伸缩、最多 5 行后滚动 |
| 侧边栏状态胶囊 | 工作台行尾每种状态一枚柔和实底胶囊（状态图标 + 数量），按待处理 > 进行中 > 未读完成排列；每个会话只计入最高优先级的一种。胶囊常显，hover 不隐藏、也不被行尾入口替换；配置页「菜单栏快捷入口」决定哪些功能页入口常显在行尾；DMS 待审批 > 0 时入口强制显示并带红点（要彻底隐藏需关闭 DMS 功能开关）；窄侧栏 + 多个状态胶囊时「工作台」标题会被自动截断以给入口让位，可在配置页关掉部分入口或拉宽侧栏。**计数剔除首页不展示的会话**（子会话 / teammate 会话与空闲空白会话），否则会数出首页两栏里根本没有的会话；首页「最近完成」的 24h 窗口与条数上限不参与计数 |
| 最近未读通知 | 最近未读的 GitHub 通知（复用通知页数据源，卡片内滚动），「查看全部」直达通知页 |

会话区刷新：外壳轮询 + 心跳重拉；首页打开时另有 60s 轻轮询刷新会话（唯一的页面自有定时器，代价是一次廉价的 fs 扫描）；运行状态不走轮询——订阅宿主会话列表（与侧边栏状态点同源）实时推送。「进行中」以宿主会话状态为准；storage 扫描的 `session.lock` flock 只是宿主列表未覆盖会话的兜底——flock 是写柄租约，会话开着即持有、与是否正在产出无关。

## 仓库页（Git / MR·PR / Issues / 自动评审）

仓库选择器下方是 **`Git` | `MR / PR` | `Issues` | `自动评审` 二级导航**；MR/PR 与 Issues 的平台与工作区全程自动识别（工作区 git remote × 本机 CLI 登录状态），无手动选择器。

### 本地 Git

随包分发的受信静态代码（来源与许可证见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)），只操作已注册工作区：

| 能力 | 说明 |
| --- | --- |
| 改动与暂存 | 已暂存 / 未暂存 / 冲突分组，diff 预览，逐文件或批量暂存 / 取消暂存；未跟踪文件暂存后才有 diff |
| 提交 | 有暂存内容时只提交暂存内容，否则自动暂存全部变更后提交；没有 Git 身份时禁用提交并提示 |
| AI 提交信息 | 选择 DSH 模型生成提交信息，只填入草稿；生成依据与提交范围一致（有暂存看暂存，否则看全部改动） |
| 历史 | 提交图、按提交信息 / 作者 / 路径搜索、分页加载、单提交详情与逐文件 diff |
| 分支 / 引用 | 检出、新建、重命名、删除分支；查看标签 / 远端；合并到当前分支 |
| 同步 | 拉取仅允许快进；推送使用 upstream 且不允许 force；可一次推送到全部远端；提交并推送 |
| 危险操作 | 放弃更改、删除文件 / 未跟踪文件需页面内确认 |

Git 子页不依赖 GitLab / GitHub CLI，只要工作区是 Git 仓库即可使用。

### MR/PR

| 能力 | 说明 |
| --- | --- |
| 列表口径 | 我的（我创建的开启中）/ 待评审（指派给我且我尚未批准）/ 全部 |
| 详情 | 标题、描述、分支、标签、合并状态、评审状态与**完整 diff** |
| 一键评审（新会话） | 在对应工作区新建会话并提交评审指令，Agent 通读变更后输出「🔴 必须修复 / 🟡 建议改进 / 💬 疑问」三级报告，完成后**直接发表为平台评论**（评论语言跟随 MR/PR）；只评审——不改码、不切换分支、不批准不合并 |
| 写操作 | 批准、合并（可选 squash / 删源分支）、评论、关闭、打开网页 |
| 助手消息按钮 | 每条定稿消息的操作行出现「提交 MR/PR」，唤醒 Agent 在**当前会话**里看 diff → commit + push → 创建 MR/PR（当前分支已有开启的则改为更新），完成后回报链接 |

### Issues

| 能力 | 说明 |
| --- | --- |
| 列表口径 | 全仓库；默认只看未关闭，状态下拉可切全部 / 已关闭 |
| 搜索与筛选 | 标题 / 描述 / 编号搜索（纯数字按编号直查）、标签、负责人、排序（更新 / 创建时间升降序）、分页 |
| 列表 | 状态、标题 + 编号 + 摘要、标签、创建者、负责人、更新时间、评论数、关联 MR/PR、操作 |
| 处理（新会话） | 开启中的 Issue 行与详情页出现「处理」：在对应工作区新建会话并提交处理指令。默认**只做分析与确认**——问题是否真实存在、复现路径与影响范围，按「🔴 已确认 / 🟡 待确认 / 💬 信息不足」给结论；不改代码、不提交、不关单、不发表评论 |
| 详情 | Markdown 描述、评论列表与发表框、右侧属性面板（状态 / 负责人 / 标签 / 关联 MR/PR / 时间） |
| 编辑 | 标题、描述、标签与负责人的增量增删 |
| 批量 | 多选后批量关闭 / 重新打开（样式化确认框，逐条执行并汇总结果） |
| 状态与反馈 | 骨架屏、失败重试、区分「筛选无结果」与「确实没有数据」的空态 |

### 自动评审

- 逐仓库开启；配置保存在本机 host，所有连接的浏览器共享，不受浏览器功能开关控制。
- 可配评审范围（指派给我为 reviewer / 含我提交的 / 全部）、触发方式、是否把报告发表为平台评论、以及冷却窗口（同一 MR/PR 的连续推送合并为一次评审）。
- 手动与自动评审共享任务记录：同一仓库与源提交复用任务，基准提交变化只让报告过期；重新评审必须显式选择，失败不自动重试。
- 已结束任务只保留有限历史索引，完整报告在 DSH 会话里；等待用户处理或状态不确定的任务会暂停后续调度。

## 配置页（按人定制的设置）

工作台顶部页签「配置」是独立的配置页（不占用列表空间，按需挂载），分五组：

### 功能与导航

仓库、Git、DMS、SLS、PingCode、技能六个功能域各自可关（GitHub 通知开关在下面的「首页」分组）；另有逐项的**菜单栏快捷入口**开关。

- 关闭功能后对应页签与侧边栏常显快捷入口消失，该功能页不再挂载，插件也不再请求该域的路由（DMS 关闭时待审批徽标 / 红点一并隐藏；仓库关闭时助手消息上的「提交 MR/PR」按钮一并隐藏；GitHub 通知关闭时首页通知区与统计卡一并隐藏——通知列表页本就不设页签 / 侧栏图标，入口在首页）。
- 快捷入口开关只影响侧栏显示，仍受功能总开关约束；DMS 有待审批时入口会强制显示并带红点。
- 开关只影响使用者自己的浏览器，随时可再打开；「配置」页本身不受开关约束，保证全部关掉后仍有入口恢复。
- 技能开关只关界面与 CLI 调用，**已装的技能仍由 DSH 直接加载**，不受该开关影响。

### 首页

GitHub 通知开关：关闭后首页通知区、统计卡与后台未读查询一并停止。

### 代码评审

可选**评审模型**：点「评审」时给新评审会话指定的模型（下拉来自 DSH 当前可路由的模型目录），留空 = 沿用 DSH 默认模型。注意 DSH 的模型选择本身会把这次选择同时记为全局默认模型，所以选定后新开的会话也默认用它——与手动在输入框里选模型同行为。逐仓库的自动评审配置在仓库页「自动评审」子页。

### Git 提交

**提交信息语言**（中文 / English）与**Git 提交信息提示词**：用于 AI 生成、一键提交与一键推送；仓库、分支、文件列表与 diff 由插件自动附加，无需占位符。

### AI 提示词

可定制四份完整指令：**评审**、**Issue 处理**、**提交 GitHub PR**、**提交 GitLab MR**。未定制时使用内置默认（中文，只保留输出契约与安全边界）；支持占位符（展开后点击插入到光标处）；每条默认收起、点标题行展开编辑，也可单独「恢复默认」。配置只存本机浏览器 localStorage，不与其他使用者同步。

## GitHub 通知

通知页查询 `gh` 在 github.com 上的当前登录账号，跨仓库列出未读通知；打开标题或外链即跳转 GitHub 并自动标为已读，也可显式标完成。通知不设顶级页签与侧栏常显入口：入口在首页（统计卡 + 最近未读通知区），列表页从首页进入。需要账号令牌具备通知访问权限（GitHub 通知 API 不支持 fine-grained PAT 或 GitHub App 令牌）。

| 作用域 | 全局（默认，`~/.agents/skills`）/ 当前工作区（`<工作区>/.agents/skills`），顶部下拉切换并持久化 |
| 卸载 | 确认弹窗（共享 ConfirmDialog，列表行内或详情页）→ `npx skills remove`；卸载后列表立即刷新 |
