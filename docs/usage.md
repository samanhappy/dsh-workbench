# 首次运行与界面行为

## 首次运行

1. 安装后**重启 DSH**，点击左侧边栏的工作台图标。
2. 当前 DSH 工作区是 git 仓库时，自动识别仓库 / 分支 / 未提交改动与平台（GitLab / GitHub）；点顶部仓库 chip 可切到其他已注册的 Git 工作区。
3. 顶部页签在**主页 / 仓库 / DMS / SLS / PingCode / 技能 / 配置**间切换，上次所在页自动记住。侧边栏工作台行本身是首页入口：点击行内常显入口之外的任意位置（含状态胶囊与行空白）或页签栏空白处即回主页，状态胶囊不随 hover 隐藏。哪些功能在行尾常显快捷入口由「配置」页的**菜单栏快捷入口**逐项控制；点击常显入口直达对应功能页；DMS 有待审批时入口会强制显示并带红点（即使关掉了 DMS 快捷入口，要彻底隐藏请关闭 DMS 功能开关）。想精简界面就在「配置」页的**功能开关**里关掉用不上的域——关闭后页签、对应常显入口一起消失，也不再请求该域，随时可再打开。
4. **SLS页**首次打开时默认最近 1 小时；若插件行配置了 `slsEnvironments`，会选中第一个环境，否则需手填 Project / Logstore（两者都非空才能查询）。点快捷区间或「查询」即开始检索（需本机 `aliyun` 已登录、且目标 Project / Logstore 已配置索引）。
5. **PingCode 页**首次打开时自动探测 python3 / 技能目录 / 令牌；任一项缺失时顶部给出具体原因与修法（如「用户令牌过期：运行 auth_user.py 重新授权」）。
6. **技能管理页**首次打开时探测 node / npx 与 `npx skills`（首次会联网拉包，稍候）；「已安装」直接读 DSH 技能根（点技能名进详情页看 SKILL.md 与它引用的支持文件），「发现技能」搜索 skills.sh 目录并一键安装——装完的通用技能新会话即可用。

## 数据新鲜度

- 面板不各自轮询：插件在后台按固定节奏刷新，刷新完成后面板自动重拉（多数情况直接命中缓存，不会重复执行 CLI）。
- 顶部刷新按钮**强制**重拉当前视图；写操作（合并、关闭、编辑、审批等）成功后相关列表与统计立即刷新。
- 因此刚在网页上改过的数据，可能要等下一次后台刷新或点一次刷新按钮才出现在面板里。
- 例外：进入 DMS 页签时若待审批列表为空，会自动强制刷新一次（绕过缓存），不必再等下一轮后台刷新。

## 仓库页

- **二级导航**：同一个仓库页内切换 **Git / MR·PR / Issues / 自动评审**；Git 子页只看当前工作区，不依赖远程 CLI。
- **平台与工作区**：全程自动（工作区 git remote × 本机 CLI 登录状态），面板没有手动平台选择器；识别不出的实例其仓库不可用。
- **本地 Git**：只操作已注册工作区；有暂存内容时只提交暂存，否则自动暂存全部改动再提交；AI 生成的提交信息先填入草稿，需要你检查后提交；拉取仅快进，推送不会 force。
- **「评审」/「处理」的出现条件**：能解析出对应工作区时按钮才出现——面板当前选中的工作区，或某个已注册工作区的 git remote 与该仓库一致。「处理」只给**开启中**的 Issue（列表行与详情页各一个入口）。
- **会话行为**：评审会复用同一提交的已有任务和报告，后台运行不切换当前会话；显式重新评审才再次执行。Issue 处理仍按点击发起独立会话。
- **指令可定制**：「配置」页里的提示词只影响本机本人；未定制时使用内置默认。
- **处理是「先确认再动手」**：默认提示词把本轮限定为分析——确认问题是否真实存在、复现路径与影响范围，不改代码、不提交、不关单、不发表评论。要直接改代码，可在该会话里继续追加指令，或先定制「Issue 处理提示词」。

## DMS / SLS

- 两者共用本机 `aliyun` 的登录凭证；未安装或未登录时面板直接给出安装 / 登录提示。
- DMS 的「待审批 / 全部」是处理人视角，可同意 / 拒绝；「我的」是提交人视角，只看自己提交的工单，不提供审批动作。
- DMS 审批的对象是**审批流实例**，不是工单号本身；拒绝必须填备注。
- SLS 的 Project / Logstore 由「环境」下拉映射，环境列表来自插件行配置 `slsEnvironments`；未配置时直接手填。新增环境只需改配置，无需改代码。

## PingCode 研发管理（可选集成）

- 页面数据来自你本机的 **pingcode 技能脚本**（`python3`），凭据在技能 `.env` 里，插件不接触。
- 项目 / 负责人 / 类型 / 状态筛选 + 关键字搜索（回车或失焦生效）；「我创建的」只在用户令牌模式下出现。
- 状态分类筛选与统计卡基于**当前已加载**的列表分页，页脚标注「已加载 N / 共 M 条」与加载更多。

## 技能管理（可选集成）

- 「已安装」列表来自 DSH 技能发现根（全局 `~/.agents/skills`，默认；顶部可切「当前工作区」）；点技能名或「详情」进独立详情页——左侧文件树列出 SKILL.md 与它引用的支持文件，右侧只读渲染当前文件，正文里的相对链接在页内打开对应文件；卸载走 CLI，确认弹窗后再执行。
- 不想让某个技能被模型自动触发、又不想卸载时，用行内的「停用」（模型不再自动触发，文件保留，随时可「启用」还原）；停用不需要联网 / skills CLI，确认弹窗后生效。
- 「发现技能」搜索 skills.sh 目录（≥2 字符，回车或点预设分类）；点结果「安装」按当前作用域与勾选的 agent 目标执行 `npx skills add --copy`。
- 安装落点由 CLI 决定并回传：默认目标「通用」（落点 = `~/.agents/skills`）；勾了 Claude Code / Codex 等会把文件装到对应 agent 目录（DSH 不一定读得到，界面有提示）。
- 新装的技能由 DSH 的 skill 监听即时发现，通常**新会话**即可用；已打开的会话不一定自动获得。

## GitHub 通知（可选集成）

- 未读通知在首页卡片与列表里展示；点标题或外链会打开 GitHub 并标为已读。通知列表页没有顶级页签，从首页进入。
- 需要 `gh` 当前账号具备通知访问权限；GitHub 通知 API 不支持 fine-grained PAT 或 GitHub App 令牌。
